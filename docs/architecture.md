# 系统架构

## 1. 决策层

模型在每个发布时点根据当时可获得的预测和储能状态更新后续购电计划。高额紧急购电惩罚使计划误差具有明显非对称性，因此计划量不能只等于均值预测；它需要通过误差情景评估或显式安全裕量校准。

## 2. 情景层

历史残差必须由同一种滚动预测方法生成。负荷与光伏残差按联合轨迹采样，并通过按天或连续 3–6 小时的时间块自举扩充场景。这样可以保留同一时段的联合偏差以及部分日内相关性。

## 3. 执行层

固定控制器只读取当前 SOC、实际负荷、实际光伏、当前合同量和充电目标。它先计算可充、可放上限，再根据当前供需缺口决定充电、放电、紧急购电、弃光和未使用合同电。

关键设计是：计划层估计期望成本时，对每个情景都调用这一个控制器。目标函数与实际执行规则因此保持一致。

## 4. 结算层

结算器不依赖优化器内部状态。它只读取价格、零点计划、最终合同和紧急购电量，分别计算正常合同、合同增加、取消违约和紧急购电费用。这一分离使独立重算成为可能。

## 5. 结果层

完整工程中，决策参数、现金账单、约束残差和图表数据都写入同一结构化结果源。论文和图表只消费冻结结果，避免在绘图或写作阶段手工填写结论数字。
